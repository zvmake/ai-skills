# fetch-insecure-web

Скилл для ИИ-агента (+ два готовых скрипта), который позволяет корректно скачивать
веб-страницы с сайтов, чей TLS-сертификат выпущен **нестандартным удостоверяющим
центром** — национальным, корпоративным, тестовым или самоподписанным, — которого
нет в системном хранилище сертификатов.

## Какую проблему решает

Обычные инструменты не могут открыть такой сайт и падают с ошибками доверия TLS:

- `ERR_CERT_AUTHORITY_INVALID` (браузерный инструмент),
- `SEC_E_UNTRUSTED_ROOT` / «выпущена центром сертификации, не имеющим доверия» (curl),
- «unable to verify the first certificate» (Node),
- webfetch «Transport error».

Опасный соблазн — «решить» это флагом `curl -k` (отключить проверку). Скилл учит
агента правильному пути: **подключить сертификат нужного УЦ как доверенный только на время одного конкретного запроса**, не отключая TLS-проверку и не устанавливая сертификат УЦ в систему.

## Как это работает (принцип)

1. **Диагностика** — кто издал сертификат сайта; полна ли цепочка; где оператор УЦ
   публикует свои сертификаты (расширения AIA «CA Issuers» и CRL Distribution Points).
2. **Добыча якоря доверия** по приоритету источников:
   `CA_PEM` (готовый файл) → кэш → `CA_URL` → адрес из AIA самого сертификата → цепочка сервера (TOFU).
3. **Криптоподтверждение** — кандидат принимается, только если он реально подписал
   листовой сертификат (`openssl verify -partial_chain`), а не по совпадению имени/даты.
4. **Запрос с пер-запросным доверием** (`curl --cacert …`, `NODE_EXTRA_CA_CERTS`,
   `REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`) и проверка результата.

Если якорь добыть не удалось — скрипт честно завершается с ошибкой и инструкцией,
а не обходит проверку.

## Как пользоваться

```bash
# Скачать страницу: якорь найдётся и проверится автоматически
bash scripts/fetch.sh "https://example.org/page" out.html

# Со своим готовым сертификатом УЦ
CA_PEM=/путь/ca.pem bash scripts/fetch.sh "https://example.org/"

# Извлечь сертификат УЦ из цепочки сервера (внутренние/тестовые стенды)
bash scripts/extract-chain-ca.sh example.org 443 ca.pem
```

Переменные окружения:

- `CA_PEM` — готовый PEM-файл якоря (если задан, больше ничего не добывается);
- `CA_URL` — адрес для загрузки кандидата (когда адрес известен вручную);
- `CA_CACHE_DIR` — каталог кэша якорей (по умолчанию — подкаталог `opencode-ca-cache` в системном temp);
- `UA` — User-Agent (по умолчанию браузерный; версию периодически обновляйте).

Код возврата `fetch.sh` ≠ 0, если ответ HTTP ≥ 400 или якорь не подтверждён.

## Принципы безопасности (жёсткие правила скилла)

- **Никогда**: `-k/--insecure`, `verify=False`, `NODE_TLS_REJECT_UNAUTHORIZED=0`.
- Никакой установки сертификатов в системное хранилище без согласия пользователя.
- Идентификация сертификата — только криптографическая (подпись листа); имя файла и дата ничего не решают.
- Если источник неизвестен (доверие «первому предъявленному», TOFU о котором скрипт
  предупреждает) — для важных операций требуется подтверждение пользователя.

## Ограничения и особенности

- Требуется: `bash ≥ 4.4`, `openssl`, `curl` (Windows — git-bash; также Linux/macOS).
- Temp-каталог берётся из `TMPDIR → TEMP → TMP → /tmp` (Windows-пути нормализуются).
- Windows/Schannel: ошибка «schannel: the revocation status is unknown» лечится
  `--ssl-no-revoke` (снимается только проверка отзыва, цепочка проверяется);
  для Node/Python файл якоря должен содержать связку «самоподписанный корень + промежуточные».
- `webfetch` и браузерный инструмент не умеют принимать свой CA — работа идёт через shell + curl.

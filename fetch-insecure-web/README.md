# fetch-insecure-web

Скилл для ИИ-агента для безопасного скачивания страниц с сайтов, чьи TLS-сертификаты не распознаются стандартным системным хранилищем. Подходит для работы с ресурсами, подписанными национальными, корпоративными, тестовыми или самоподписанными центрами сертификации (УЦ).

## Зачем это нужно

Обычные утилиты и браузерные движки блокируют такие сайты с типовыми ошибками доверия TLS:

* `ERR_CERT_AUTHORITY_INVALID` (в браузере);
* `SEC_E_UNTRUSTED_ROOT` / «выпущена центром сертификации, не имеющим доверия» (в `curl`);
* `unable to verify the first certificate` (в среде Node.js);
* `Transport error` (во встроенном инструменте `webfetch`).

Частое, но опасное решение — заглушить проверку флагом `curl -k`. Этот скилл решает проблему безопасно: **подключает нужный сертификат УЦ только на время конкретного запроса**. Системное хранилище остаётся чистым, а проверка TLS не отключается.

## Принцип работы

1. **Диагностика:** скрипт проверяет издателя сертификата, полноту цепочки и адреса публикации сертификатов УЦ через расширения AIA (`CA Issuers`) и CRL Distribution Points.
2. **Поиск якоря доверия:** сертификат подбирается по строгой цепочке приоритетов:
   `CA_PEM` (готовый локальный файл) → локальный кэш → `CA_URL` (прямая ссылка) → адрес из AIA самого сертификата → цепочка сервера (TOFU).
3. **Криптографическая проверка:** кандидат принимается только после валидации подписи листового сертификата (`openssl verify -partial_chain`). Совпадение имён, дат или доменов в расчёт не берётся.
4. **Изолированный запрос:** выполняется обращение с точечным доверием (`curl --cacert …`, `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE` или `SSL_CERT_FILE`) и проверкой кода ответа.

Если подтверждённый якорь найти не удалось, скрипт завершает работу с понятной ошибкой и инструкцией по исправлению вместо небезопасного обхода.

## Использование

```bash
# Автоматический поиск, проверка якоря и скачивание страницы
bash scripts/fetch.sh "https://example.org/page" out.html

# Скачивание с явным указанием локального сертификата УЦ
CA_PEM=/путь/к/ca.pem bash scripts/fetch.sh "https://example.org/"

# Извлечение сертификата УЦ из цепочки сервера (для внутренних и тестовых стендов)
bash scripts/extract-chain-ca.sh example.org 443 ca.pem
```

### Переменные окружения

* `CA_PEM` — прямой путь к PEM-файлу якоря (отключает автоматический поиск).
* `CA_URL` — прямая ссылка для загрузки сертификата УЦ вручную.
* `CA_CACHE_DIR` — каталог для кэширования проверенных якорей (по умолчанию — папка `opencode-ca-cache` в системном temp).
* `UA` — кастомный User-Agent (по умолчанию используется актуальный браузерный заголовок).

> Скрипт `fetch.sh` возвращает ненулевой код ошибки, если валидация якоря провалилась или сервер вернул HTTP-статус `>= 400`.

## Правила безопасности

* **Полный запрет небезопасных флагов:** никаких `-k / --insecure`, `verify=False` или `NODE_TLS_REJECT_UNAUTHORIZED=0`.
* **Чистота ОС:** сертификаты не импортируются в системное хранилище операционной системы.
* **Строгая криптография:** доверие строится только на математической проверке подписи листа.
* **Контроль TOFU:** при первом предъявлении неизвестного сертификата (Trust On First Use) агент предупреждает пользователя и требует явного подтверждения для критичных операций.

## Системные требования и нюансы

* **Окружение:** `bash >= 4.4`, `openssl`, `curl`. Поддерживаются Linux, macOS и Windows (через Git Bash).
* **Временные файлы:** путь к каталогу temp определяется по цепочке `TMPDIR → TEMP → TMP → /tmp` (пути Windows автоматически нормализуются под UNIX-формат).
* **Особенности Windows/Schannel:** ошибка `schannel: the revocation status is unknown` обходится ключом `--ssl-no-revoke` (отключается только проверка отзыва, сама цепочка доверия остаётся активной). Для Node.js и Python файл якоря должен содержать полную связку: корень + промежуточные сертификаты.
* **Инструменты агента:** поскольку встроенные браузерные движки и `webfetch` не поддерживают динамическую подмену CA на лету, взаимодействие происходит через связку shell и `curl`.
